# SNMP Architecture — Datacenter Network Simulator

**Version:** 1.0 · **Last updated:** 2026-06-17

This document catalogs the SNMP plane of the simulator: which simulated device
classes run an SNMP agent, what metrics each one exposes, and the exact OIDs
served. It complements [`PROTOCOL_ARCHITECTURE.md`](PROTOCOL_ARCHITECTURE.md)
(which covers *which protocol runs where* across SNMP / gNMI / sFlow / Redfish /
BACnet); this file drills into the SNMP layer alone.

All OIDs below are generated by `core/snmprec_generator.py` into
`datasets/snmp/<ip>.snmprec` files and served by the `snmpsim` subprocess
(`simulator/snmpsim_controller.py`), one UDP/161 listener bound per IP.
Dynamic OIDs are re-patched every StateStore tick (`patch_metrics`) so polled
values move with the live simulation.

---

## 1. How SNMP is served

| Concern | Detail |
|---|---|
| Protocol version | SNMPv2c (community-based) |
| Port | UDP **161** (queries) · **1161** for the SET agent (`core/snmp_set_agent.py`) |
| Community string | **equals the device IP** — poll `10.0.1.5` with community `10.0.1.5` |
| Dataset format | `OID|TYPE_CODE|VALUE` per line (snmprec) |
| Runtime | `snmpsim` subprocess, one listener bound per IP |
| Live updates | `SNMPRecGenerator.patch_metrics()` rewrites dynamic OIDs each tick; LLDP/CDP/MAC/STP patched separately and only on topology change |

**snmprec type codes** (from the generator header):

| Code | SNMP type | Code | SNMP type |
|---|---|---|---|
| `2`  | Integer32 | `44` | Counter64 |
| `4`  | OctetString (UTF-8) | `64` | IPAddress |
| `4x` | OctetString (hex) | `65` | Counter32 (enterprise use) |
| `6`  | OID | `66` | Gauge32 |
| `41` | Counter32 | `67` | TimeTicks |
| `42` | Gauge32 | `70` | Counter64 |

## 2. Supported SNMP operations (methods)

The simulator runs **two SNMP listeners** with different operation sets, plus an
outbound notification path:

| Operation | Port 161 (`snmpsim`, read plane) | Port 1161 (`SnmpSetAgent`, mgmt plane) | Notes |
|---|---|---|---|
| **GET** (poll) | ✔ | ✔ | single-OID read |
| **GETNEXT** | ✔ | ✔ | lexicographic next — basis of WALK |
| **GETBULK** | ✔ | ✘ | bulk read; only the snmpsim agent |
| **WALK / BULKWALK** | ✔ | ✔ (via GETNEXT) | subtree traversal |
| **SET** (write) | ✘ | ✔ | snmpsim datasets are read-only; writes go to 1161 |
| **TRAP / NOTIFY** | outbound only | — | SNMPv2c traps pushed by `core/trap_engine.py` (see §9) |

Both listeners use the same convention: **community string = device IP**.

### 2.1 Read / poll plane — `snmpsim`, UDP 161

Serves every metric OID in this document (sections 4–8). Read-only: `GET`,
`GETNEXT`, `GETBULK`, and therefore `snmpwalk` / `snmpbulkwalk`. There is **no
SET** here — the `.snmprec` datasets are static files mutated only internally by
the StateStore tick.

```bash
# Poll one OID (sysDescr)
snmpget    -v2c -c 10.50.0.4 <agent>:161 1.3.6.1.2.1.1.1.0
# Walk the whole interface table
snmpwalk   -v2c -c 10.50.0.4 <agent>:161 1.3.6.1.2.1.2.2.1
# Bulk-walk the full tree
snmpbulkwalk -v2c -c 10.50.0.4 <agent>:161 1.3.6.1
```

### 2.2 Management / write plane — `SnmpSetAgent`, UDP 1161

A separate hand-rolled agent (`core/snmp_set_agent.py`) implementing `GET`,
`GETNEXT`, `SET` (PDU tags 0 / 1 / 3). No root/admin needed (high port). It does
**not** serve device metrics — only **read/write configuration** for a DCIM
under test. Three writable OID groups:

| OID group | Base | Type | What it sets |
|---|---|---|---|
| **Rule thresholds** | `1.3.6.1.4.1.99999.3.x` | Integer | Per-device alert thresholds — HighCPU `.1.0`, HighCPUSustained `.2.0`, CPUNormal `.3.0`, HighMemory `.4.0`, HighTemperature `.6.0`, RackFailure min `.9.0`, sensor temp/humidity/dewpoint/airflow `.10–.21` (airflow ×10) |
| **System identity** | `1.3.6.1.2.1.1.4/5/6.0` | OctetString | sysContact, sysName, sysLocation |
| **Asset / location** | `1.3.6.1.4.1.99999.4.x` | Str/Int | country, datacenter city, datacenter, floor, room, rack row/num/unit, model, power draw W |

```bash
# Read the HighCPU threshold for device 10.50.0.4
snmpget -v2c -c 10.50.0.4 <agent>:1161 1.3.6.1.4.1.99999.3.1.0
# Set the HighCPU threshold to 85 %
snmpset -v2c -c 10.50.0.4 <agent>:1161 1.3.6.1.4.1.99999.3.1.0 i 85
# Walk every management OID
snmpwalk -v2c -c 10.50.0.4 <agent>:1161 1.3.6.1.4.1.99999.3
```

A threshold not explicitly set falls back to the global rule default. A
successful threshold SET re-arms the rule engine for that device; identity/asset
SETs mutate the live `Device` object.

> **OID-space note:** enterprise branches `.3` and `.4` carry *different*
> meanings on the two ports. On **161** `.3.x` = generator status / `.4.x` = UPS
> status (read metrics). On **1161** `.3.x` = rule thresholds / `.4.x` = asset
> data (writable config). They never collide because they live on separate
> listeners.

### 2.3 Test tooling

`testscripts/test_snmp.py <ip> [flags]` exercises the read plane (GET + WALK)
with type-aware section flags: `--full` (auto-detect), `--bmc`, `--switch`,
`--router`, `--ups`, `--pdu`, `--sensor`, `--interfaces`, `--agent <host>`,
`--port`, `--community`. `testscripts/test_snmp_set.py` exercises the 1161 SET
path; `testscripts/test_snmp_mgmt.py` walks the management tree.

## 3. Which devices run SNMP

Addressing follows two rules in `SNMPRecGenerator`:

- **`snmp_address()`** — switches/routers/firewalls/LBs/OOB/power/sensor gear
  answer on the **OOB mgmt IP** (`mgmt_ip`) when present, else `ip_address`.
  Servers answer their **OS agent** on the **production IP**.
- **`bmc_address()`** — a server with an OOB connection *also* exposes a second
  **BMC SNMP agent** on the **mgmt IP** (same address Redfish binds).

| Device type | SNMP agent? | Bind IP | MIB families served |
|---|---|---|---|
| Router | ✔ | mgmt IP | System, IF-MIB, IP, LLDP/CDP, BGP4-MIB, (Cisco perf/env) |
| Switch | ✔ | mgmt IP | System, IF-MIB, IP, LLDP/CDP, BRIDGE-MIB (MAC/STP), (Cisco) |
| Firewall | ✔ | mgmt IP | System, IF-MIB, IP, LLDP, BGP4-MIB, (Cisco) |
| Load balancer | ✔ | mgmt IP | System, IF-MIB, IP, LLDP, (Cisco) |
| OOB switch | ✔ | mgmt IP | System, IF-MIB, IP, LLDP (mgmt-port neighbors) |
| **Server (OS agent)** | ✔ | **prod IP** | System, IF-MIB, IP, HOST-RESOURCES, UCD-SNMP, ENTITY-SENSOR |
| **Server (BMC agent)** | ✔ | **mgmt IP** | System + enterprise `.26` (power state, temps, fans, PSUs) |
| Environmental sensor | ✔ | mgmt IP | Vendor sensor MIB (Raritan / Vertiv Geist / APC NetBotz) |
| UPS | ✔ | mgmt IP | UPS-MIB (RFC 1628) + enterprise `.4` |
| PDU / Floor PDU | ✔ | mgmt IP | Enterprise `.5` + per-outlet table `.5.20.1` |
| Generator | ✔ | mgmt IP | Enterprise `.7` |
| CRAH | ✔ | mgmt IP | Enterprise `.24` (ships native comm card) |
| CDU | ✔ | mgmt IP | Enterprise `.25` (ships native comm card) |
| **RPP** | ✘ | — | Passive breaker panel — no agent |
| **Chiller / Pump / Cooling tower / Valve** | ✘ | — | BACnet/Modbus-native; no SNMP card (telemetry reaches IT via BMS) |

> Devices with no `mgmt_ip` in a topology that *has* an OOB layer are skipped
> entirely (no management path → unreachable via SNMP). Servers are the
> exception — they always get an OS-agent dataset on the production IP.

## 9. SNMP traps (`core/trap_definitions.py`)

Traps are SNMPv2c notifications sent by `core/trap_engine.py`, driven by the
rule engine (`core/trap_rules.py`) plus direct BMC platform events. Standard
trap OIDs use `1.3.6.1.6.3.1.1.5.x`; enterprise traps use `1.3.6.1.4.1.99999`.

### 9.1 Standard / protocol traps

| OID | Trap | Severity |
|---|---|---|
| `1.3.6.1.6.3.1.1.5.1` | coldStart | informational |
| `1.3.6.1.6.3.1.1.5.2` | warmStart | informational |
| `1.3.6.1.6.3.1.1.5.3` | linkDown | major |
| `1.3.6.1.6.3.1.1.5.4` | linkUp | informational |
| `1.3.6.1.6.3.1.1.5.5` | authenticationFailure | major |
| `1.3.6.1.2.1.15.0.2` | bgpSessionDown | critical |
| `1.3.6.1.2.1.33.2.0.1` | upsOnBattery | critical |
| `1.3.6.1.2.1.33.2.0.2` | upsLowBattery | critical |

### 9.2 General device traps — `1.3.6.1.4.1.99999.1.x`

`.1` cpuHighUsage · `.2` memoryHighUsage · `.3` temperatureAlert · `.4`
linkFlap · `.5` rackFailure · `.6` humidityAlert · `.7` dewPointAlert · `.8`
airflowAlert · `.9–.12` sensor mid/exhaust temp high/normal.

### 9.3 UPS traps — `.2.1–.2.17`

batteryNormal, utilityPowerRestored, outputOverload, outputNormal, fanFailure,
batteryFailure, batteryDisconnected, chargerFailure, inputVoltageHigh/Low,
frequencyOutOfRange, rectifierFailure, phaseFailure, batteryLowHealth,
batteryHealthRestored, bypassActive, bypassCleared.

### 9.4 Generator traps — `.3.1–.3.7`

generatorRunning, generatorStopped, generatorLowFuel, generatorLowCoolant,
generatorBatteryFailure, generatorTransferSwitch, generatorOvercrank.

### 9.5 PDU traps — `.6.1–.6.19`

outletOn/Off, breakerTripped, loadHigh/Critical, voltageHigh/Low,
phaseImbalance, powerFactorLow, outletFailure, smokeDetected,
outletCurrentHigh, groundFault, pduFrequencyFault/Normal, pduTempHigh/Normal,
pduHumidityHigh/Normal.

### 9.6 Server BMC platform events — `.26.0.1 / .26.0.2`

`serverPowerOff` (major) / `serverPowerOn` (informational) — emitted by the BMC
on the mgmt IP, fire even while the chassis is powered off.

Per-device-type trap applicability is defined by `APPLICABLE_TRAPS` (and
`_SENSOR_MODEL_TRAPS` for sensors); switches gain `bgpSessionDown` only when the
model is in `_BGP_CAPABLE_SWITCH_MODELS`.
